# 海龟汤投稿（Pull Request）

这个目录就是投稿箱：**每个 `.json` 文件 = 一道汤**。  
维护者人工核查通过并合并后，服务会在**下一次启动 / 部署**时自动把文件加载进题库（`source: "pr"`）。删除文件并重新部署即可下架。

## 一、怎么投

1. **Fork** 仓库 <https://github.com/kshuazhi/turtle-soup>。
2. 在你的副本里进入 `submissions/`，新建一个 JSON 文件，文件名用英文或拼音，例如 `midnight-knock.json`（**不要**用中文文件名）。
3. 按下面的格式填好内容。
4. 提交 **Pull Request**：
   - 标题以 `[汤]` 开头，例如 `[汤] 午夜敲门`
   - 模板选择 **海龟汤投稿**（`turtle-soup.md`）
   - 说明里写清汤名和一句话简介
5. 等维护者人工核查。合并后不用做别的，下一次部署就会上线。

> 普通代码 / 文档 PR 请使用 **default** 模板，标题不要加 `[汤]`，也不要往这个目录塞代码；两类 PR 互不干扰，分开审核。

## 二、文件格式

```json
{
  "title": "汤的名字（40 字以内）",
  "surface": "汤面：只写谜面，不要透露答案",
  "solution": "汤底：完整、唯一、能解释汤面所有细节的真相",
  "hints": ["提示一（可选）", "提示二（可选）"],
  "tags": ["悬疑", "经典"]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 40 字以内 |
| `surface` | 是 | 汤面，1000 字以内，不要出现答案 |
| `solution` | 是 | 汤底，3000 字以内，要能解释汤面的所有细节 |
| `hints` | 否 | 最多 8 条，每条 200 字以内，按从含糊到直白的顺序 |
| `tags` | 否 | 最多 5 个，每个 12 字以内 |

以 `_` 开头的文件（例如 `_example.json`）只是示例，不会被加载。

## 三、内容要求

- 不含违规、违禁、血腥猎奇、真实个人信息或他人隐私；
- 不抄袭已有题目；
- 汤面只描述结果，汤底能自洽地解释全部细节；
- 维护者保留拒绝或要求修改的权利。

## 四、审核流程

```
提交 PR → 维护者人工核查（内容 / 合规）→ 合并到 main → 下一次部署自动入库
```
